# Checklist เรื่องกฎหมาย การเงิน และข้อมูลส่วนบุคคล

> เอกสารนี้เป็นรายการสิ่งที่ควรตรวจสอบ **ไม่ใช่คำแนะนำทางกฎหมายหรือภาษี**
> ก่อนรับเงินจริง ควรปรึกษาทนายความและนักบัญชี/สรรพากร

## บัญชีรับเงิน

- [ ] ระบุผู้จัดงานตัวจริง (บุคคลธรรมดา / สมาคม / บริษัท) และชื่อบัญชีที่จะรับเงิน
- [ ] ใช้บัญชีแยกสำหรับงานนี้ ไม่ปนกับเงินส่วนตัว (เงินคนพันคนเข้าบัญชีส่วนตัวอาจถูกธนาคารตรวจสอบหรือระงับชั่วคราว)
- [ ] ถ้าใช้ gateway: สมาคมที่จดทะเบียนแล้วมักผ่านง่ายกว่าบุคคลธรรมดา เตรียมเอกสาร (หนังสือรับรองนิติบุคคล/ใบจดทะเบียน, บัตร ปชช. กรรมการผู้มีอำนาจ, สำเนาหน้าบัญชีในนามสมาคม, หนังสือมอบอำนาจถ้าผู้สมัครไม่ใช่กรรมการ)
- [ ] ยื่นสมัคร gateway ล่วงหน้า (การอนุมัติอาจใช้เวลาเป็นสัปดาห์) ระหว่างรอใช้ PromptPay + ตรวจสลิปเป็นแผนสำรอง
- [ ] ชื่อบัญชีที่สมัครกับ gateway ต้องตรงกับบัญชีรับเงิน
- [ ] ไม่เปลี่ยนบัญชีรับเงินกลางช่วงเปิดรับสมัคร (จะจับคู่ยอดสับสน)
- [ ] ตรวจเงื่อนไขของบริการตรวจสลิปที่เลือก (รับบัญชีบุคคลธรรมดาไหม ต้องยืนยันตัวตนไหม โควต้าเท่าไหร่)

## ภาษี

- [ ] ปรึกษานักบัญชี/สรรพากรว่ารายได้จากงานนี้ต้องยื่นอย่างไร (ผู้จัด และตัวคุณถ้ามีค่าบริการ)
- [ ] ออกใบเสร็จ/ใบกำกับภาษีให้ผู้จัด/นักวิ่งตามที่จำเป็น
- [ ] ถ้าขายระบบให้ผู้จัดอื่น: ตรวจเรื่องจดทะเบียนธุรกิจและภาษีมูลค่าเพิ่ม

## การถือเงินแทนผู้อื่น (ถ้าขายระบบ)

- [ ] อย่าให้เงินนักวิ่งเข้าบัญชีของคุณก่อนโอนต่อให้ผู้จัด (จะกลายเป็นตัวกลางถือเงิน มีผลทางภาษีและกฎหมาย)
- [ ] ให้เงินเข้าบัญชีผู้จัดโดยตรง คุณเก็บแค่ค่าบริการ หรือใช้ gateway ที่รองรับแบบ sub-merchant

## PDPA (ข้อมูลส่วนบุคคลและข้อมูลสุขภาพ)

ระบบเก็บ ชื่อ วันเกิด เบอร์โทร อีเมล เลขบัตรประชาชน/พาสปอร์ต (ถ้าเก็บ) ผู้ติดต่อฉุกเฉิน กรุ๊ปเลือด โรคประจำตัว/แพ้ยา ซึ่งบางส่วนเป็นข้อมูลอ่อนไหว

- [ ] เก็บเฉพาะข้อมูลที่จำเป็น **ถ้าไม่จำเป็นต้องใช้เลขบัตรประชาชน ไม่ต้องเก็บ** (ตอนนี้ฟิลด์ `IdCardOrPassport` ใน schema เป็นตัวเลือก)
- [ ] ประกาศความเป็นส่วนตัว (Privacy Notice) บอกว่าเก็บอะไร เพื่ออะไร นานเท่าไหร่ ใครเข้าถึงได้
- [ ] ขอความยินยอมที่ชัดเจนตอนสมัคร (ติ๊กยอมรับ) โดยเฉพาะข้อมูลสุขภาพ
- [ ] ถ้าสมัครให้คนอื่น (เพื่อน/เด็ก) ผู้สมัครต้องมีสิทธิ์/ได้รับความยินยอมจากเจ้าของข้อมูลหรือผู้ปกครอง
- [ ] ถ้าเป็นผู้พัฒนาระบบให้ผู้จัดอื่น: ทำสัญญาประมวลผลข้อมูล (Data Processing Agreement) กำหนดว่าใครเป็นผู้ควบคุมข้อมูล
- [ ] จำกัดสิทธิ์เข้าถึงข้อมูลสุขภาพในหลังบ้าน (เฉพาะบทบาทที่จำเป็น) และบันทึก Audit log
- [ ] เข้ารหัสข้อมูลอ่อนไหว, เข้ารหัสการเชื่อมต่อ (HTTPS), เข้ารหัส backup
- [ ] กำหนดระยะเวลาเก็บและขั้นตอนลบข้อมูลหลังจบงาน (รวม backup และสำเนาบนเครื่องพัฒนา)
- [ ] มีช่องทางให้เจ้าของข้อมูลขอแก้ไข/ลบข้อมูล
- [ ] แผนรับมือเหตุข้อมูลรั่ว (ใครแจ้งใคร ภายในกี่ชั่วโมง ตามกฎหมาย)

## บริการและข้อมูลภายนอก

- [ ] ตรวจ **license ของข้อมูลจังหวัด/อำเภอ/ตำบล** ที่นำมา seed (โดยเฉพาะถ้าจะขายเชิงพาณิชย์) และความทันสมัยของข้อมูล
- [ ] ตรวจเงื่อนไขการใช้งาน **LINE Messaging API / LINE Login** และแพ็กเกจ OA (โควต้าข้อความ, ข้อจำกัดการส่งข้อความโปรโมชัน)
- [ ] ตรวจเงื่อนไขเชิงพาณิชย์ของแพ็กเกจฟรีบนแพลตฟอร์มที่ใช้โฮสต์ (ถ้าใช้ Vercel/Cloudflare Pages ฯลฯ)
- [ ] ตรวจเครื่องหมายการค้าของชื่อโปรเจกต์ (ฐานข้อมูลกรมทรัพย์สินทางปัญญา) และความว่างของโดเมน/ชื่อเพจ/LINE OA ID
- [ ] ฟอนต์ที่ใช้ (Prompt, Noto Sans Thai) เป็นฟอนต์เสรีผ่าน Google Fonts ตรวจ license ถ้านำไปใช้ในงานพิมพ์

## เงื่อนไขกับนักวิ่ง

- [ ] เงื่อนไขการสมัคร นโยบายคืนเงิน/โอนสิทธิ์/เปลี่ยนระยะ ที่แสดงก่อนจ่ายเงิน
- [ ] ข้อตกลงรับความเสี่ยงและสุขภาพของนักวิ่ง (ตามที่ผู้จัดกำหนด)
- [ ] ถ้าบวกค่าบริการให้นักวิ่ง ต้องแสดงยอดรวมชัดเจนก่อนชำระ
