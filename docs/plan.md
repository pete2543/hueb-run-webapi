# แผนโปรเจกต์ HuebRun

เอกสารนี้สรุปการตัดสินใจที่คุยกันมาทั้งหมด พร้อมเหตุผล เพื่อให้กลับมาอ่านทีหลังแล้วรู้ว่าทำไมถึงเลือกแบบนี้

## 1. เป้าหมายและขอบเขต

- งานเดิน-วิ่ง 1 งาน ประมาณ **1,000 คน** ระยะ **3 / 5 / 10 กม.** แต่ละระยะมีโควตาและราคาแยกกัน
- ใช้ซ้ำข้ามปีได้ (ทุกอย่างผูกกับ `Event` ปีละงาน)
- รองรับ **สมัครเป็นกลุ่ม**: คนเดียวสมัครให้เพื่อนหลายคนในใบสมัครเดียวและจ่ายเงินครั้งเดียว
- รับของได้ 2 แบบ: **รับเองหน้างาน** หรือ **ส่งไปรษณีย์** (ค่าส่งคิดต่อใบสมัคร)
- มีโค้ดส่วนลด และราคา early bird ตามช่วงเวลา
- มีเช็กอินรับบิบด้วย QR
- ช่องทาง: เว็บลงทะเบียน, LINE OA (แจ้งเตือน/ประกาศ), Facebook Page (ประชาสัมพันธ์อย่างเดียว ไม่เชื่อมระบบ)
- มีหลังบ้านสำหรับผู้จัดและสตาฟ

## 2. การตัดสินใจที่สรุปแล้ว

| หน้าบ้าน | Next.js + Tailwind + shadcn/ui | mobile-first, ฟอร์ม/ตารางทำง่าย |
| ฐานข้อมูล | PostgreSQL | |

| กันสมัครเกินโควตา | transaction + atomic counter + concurrency token (xmin) + check constraint | ปลอดภัยที่ชั้น DB ไม่ต้องพึ่งคิว |

## 3. สถาปัตยกรรม

```
นักวิ่ง ── Cloudflare ── Next.js (เว็บ) ──┐
LINE OA ── LIFF/LINE Login ──────────────┤
แอดมิน/สตาฟ ── Next.js (/admin) ─────────┤
                                         ▼
                              ASP.NET Core Web API ── PostgreSQL
                                   │  (Hangfire jobs ใน DB เดียวกัน)
                                   ├─ ตรวจสลิป (บริการภายนอก)
                                   └─ LINE Messaging API (push)
```

- เปิดแค่พอร์ต 80/443 ผ่าน Cloudflare ปิดพอร์ต PostgreSQL จากภายนอก
- เซิร์ฟเวอร์ในโซนสิงคโปร์ (ใกล้ไทย) ขนาดเริ่มต้นประมาณ 2 vCPU / 2–4GB (ยืนยันด้วย load test)
- PostgreSQL อยู่เครื่องเดียวกับ API หรือเครื่องที่สองในเครือข่ายภายในของผู้ให้บริการเดียวกัน ไม่ควรให้ API คุยกับ DB ข้ามอินเทอร์เน็ต

## 4. Flow การสมัครและชำระเงิน

1. นักวิ่งเลือกระยะ/ไซซ์เสื้อ กรอกข้อมูล (เพิ่มเพื่อนได้) เลือกรับของ ใส่โค้ดส่วนลด
2. API สร้าง `Order` สถานะ `Pending` และ **จองโควตา/สต็อกเสื้อ/โค้ด** ใน transaction เดียว ตั้ง `ExpiresAt` (ค่าเริ่มต้น 30 นาที)
3. ระบบสร้าง QR PromptPay ตามยอดรวม **บวกเศษสตางค์ไม่ซ้ำ** ต่อ Order (`PayableAmount`) เพื่อจับคู่ยอดโอน
4. นักวิ่งโอนแล้วอัปโหลดสลิป
5. ระบบส่งสลิปไปตรวจ เทียบยอด บัญชีปลายทาง เวลา และเลขอ้างอิงสลิป
   - ผ่าน → `Paid` ออกเลขบิบและ QR เช็กอิน ส่ง LINE ยืนยัน
   - ไม่แน่ใจ → เข้าคิว **ตรวจมือ** ในหลังบ้าน
   - ไม่ผ่าน/สลิปซ้ำ → `Rejected` แจ้งผู้สมัคร
6. หมดเวลา → Hangfire เปลี่ยนเป็น `Expired` และคืนโควตา/สต็อก/โค้ด
7. ทุกการกระทำของแอดมินบันทึกใน `AuditLog`

เทคนิคกันปัญหา: unique constraint ที่ `SlipHash` และ `SlipTransRef`, unique ของ `PayableAmount` เฉพาะ Order ที่ยัง `Pending`, เลขบิบ unique ต่อ Event

## 5. การแจ้งเตือน LINE

- ต้องรู้ LINE userId: ให้สมัครผ่าน **LINE Login/LIFF** และชวนเพิ่มเพื่อน OA
- ทุกข้อความเขียนลงตาราง `Notification` (outbox) ก่อน แล้วให้ Hangfire ส่ง มี retry และ `DedupeKey` กันส่งซ้ำ
- เทมเพลตแก้ได้จากหลังบ้าน (`NotificationTemplate`) ตัวอย่างที่ seed ไว้: order_created, order_paid, order_expiring, order_expired, payment_rejected, shipping_sent, event_reminder
- ประกาศถึงนักวิ่งหลายคนใช้ `Broadcast` (เลือกระยะ, เฉพาะคนที่จ่ายแล้ว, ตั้งเวลาได้)
- **ข้อควรระวัง**: push message มีโควต้าตามแพ็กเกจ LINE OA ตรวจโควต้า/ราคาปัจจุบันก่อน ส่งเฉพาะข้อความที่จำเป็น ผู้ที่ไม่ใช้ LINE ให้มีอีเมลสำรอง

## 6. Roadmap

| เฟส | งาน | ผลลัพธ์ |
|---|---|---|
| 0 (ตอนนี้) | DB schema + เดโม UI + เอกสาร | ทิศทางชัด |
| 1 | ทำหน้าบ้านตามเดโม ใช้ mock ตาม `api-contract.md` | หน้าเว็บทำงานได้กับข้อมูลจำลอง |
| 2 | หลังบ้านหลัก: สร้าง Order + จองโควตาใน transaction, payment/slip, ออกเลขบิบ, job หมดเวลา | สมัครและจ่ายเงินได้จริง |
| 3 | หลังบ้านแอดมิน + LINE (outbox, เทมเพลต, ประกาศ) + เช็กอิน | ใช้งานจริงได้ครบ |
| 4 | Load test, ซ้อมเคสพัง (สลิปปลอม/ซ้ำ, แย่งที่นั่งสุดท้าย), deploy, เปิดจริง | พร้อมรับสมัครงานแรก |
| 5 (อนาคต) | payment gateway, multi-tenant (ตาราง Organizer), ตั้งราคาและขายให้ผู้จัดอื่น | ผลิตภัณฑ์ |

## 7. ความเสี่ยงสำคัญ

- **เงินเข้าบัญชีส่วนตัว**: รับเงินคนพันคนเข้าบัญชีส่วนตัวอาจถูกธนาคารตรวจสอบ/ระงับ และปนกับเงินส่วนตัว ควรใช้บัญชีแยกสำหรับงาน หรือบัญชีของสมาคม/ผู้จัด
- **ถือเงินแทนผู้จัดอื่น (ถ้าขายระบบ)**: ถ้าเงินเข้าบัญชีเราก่อนโอนต่อ จะกลายเป็นตัวกลางถือเงิน มีผลทางภาษีและกฎหมาย แนะนำให้เงินเข้าบัญชีผู้จัดโดยตรง
- **สลิปปลอม**: บริการตรวจสลิปช่วยได้ แต่ควรสุ่มตรวจยอดกับแอปธนาคาร
- **ล่มวันเปิดรับสมัคร**: load test ล่วงหน้า (เช่น k6), ใช้ Cloudflare, พิจารณาเปิดเป็นรอบ
- **ข้อมูลส่วนบุคคล/สุขภาพ (PDPA)**: ดู `legal-checklist.md`
- **LINE push เกินโควต้า**
